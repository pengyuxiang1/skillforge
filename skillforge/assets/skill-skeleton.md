生产超级 skill 时，按此骨架创建文件。**按需裁剪**——多数 skill 不需要全部部件。

## 目录结构

```
{skill-name}/
├── SKILL.md                    # 主流程（必须）
├── scripts/
│   └── {name}_guide.py         # 引导脚本（Stage 3 判定）
├── assets/
│   └── {state}.md              # 状态文件模板（如需要状态文件）
└── references/
    ├── {topic}.md              # 方法论细节（按需）
    └── cases/                  # 仅 skillforge 自己需要
```

## 🔁 引导机制（每个动作前先跑）

> {任务描述}是长任务，可能跨会话。**不要凭记忆推进**，跑引导脚本拿当前状态。

```bash
# 新建任务
python3 {脚本路径} --new "<任务名>"

# 每个动作前先跑
python3 {脚本路径} <state.md路径>

# 阶段推进
python3 {脚本路径} <state.md路径> --advance
```

## 状态文件骨架

**顶部必须钉引导指令**（这是 AI 必读位置）：

```markdown
# {任务类型}：{任务名}

> 🔁 **引导机制 —— 每个动作前先跑，不要凭记忆推进**
>
> ```bash
> python3 {脚本路径} {本文件路径}
> ```
>
> 它会读本文件、返回：**当前阶段 / 下一步做什么 / 怎么做 / 检查清单 / 缺什么**。
> 阶段完成后跑 `--advance` 推进。

## Stage 0 {阶段名}

- 状态：🟡
- {字段1}：
- {字段2}：

## Stage 1 {阶段名}

- 状态：⏸
```

**状态标记约定**：`✅` 完成 / `🟡` 进行中 / `⏸` 未开始（脚本按此解析）。

## 检查清单（创建前逐项确认）

- [ ] SKILL.md 的 `description` 写清了触发场景（这是调度依据）
- [ ] 状态有语义（不是 step1/step2）
- [ ] 每个状态的判定标准**能写成检查代码**
- [ ] 引导脚本零依赖、只读不写
- [ ] 引导指令钉在状态文件顶部
- [ ] hook（如有）用 command 类型、fail-open、有开关
- [ ] hook 的工具名**去 bundle 里 grep 验证过**（见 hook-spec.md 坑 1）
- [ ] 造了违规样本验证门禁能拦住（L3）
