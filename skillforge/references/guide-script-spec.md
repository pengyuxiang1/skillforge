Stage 3 引导脚本的实现依据。核心目标：**让 AI 不离题**。

## 一、为什么需要引导脚本

长任务的失败模式：AI 跑着跑着忘了下一步、忘了约束、忘了判定标准。

根因是**提示词会被上下文稀释**——SKILL.md 里写的协议，任务跑长了就被压到注意力边缘。

解法：把"下一步该做什么"从**写死的文字**变成**每次现场拉取的状态**。

```
SKILL.md 里的协议     → 静态，会沉底
引导脚本的返回值      → 动态，每次都重新算
```

## 二、五条设计要求

| # | 要求 | 原因 |
|---|------|------|
| 1 | **零依赖**（Python 标准库） | 换机器/换环境不会跑不起来 |
| 2 | **只读不写** | 状态文件由 AI 更新，脚本只读——职责清晰，避免双写冲突 |
| 3 | **零参数负担** | 一个命令，路径可省略（自动找最新）；"想起来要调"的成本要极低 |
| 4 | **结构化返回** | JSON 供 AI 读，文本供人读，两种模式 |
| 5 | **宽松解析** | 容忍表格/标题/列表多种写法；解析不到就提示补齐，不报错退出 |

## 三、返回结构

必须包含这五类信息：

```json
{
  "stage": "verify",
  "stage_title": "Stage 3 逐条验证",
  "progress": "2/5",
  "next": "验证 H3：定时器调用链",
  "how": "找 UpdateInterAct 调用链 + 是否有定时任务",
  "gaps": ["H3 缺证据出处"],
  "reminder": "标 🟢 前必须有证据；严禁把 [推断] 当结论"
}
```

- `next` — **做什么**（动作）
- `how` — **怎么做**（具体到命令/文件/索引集）
- `gaps` — **缺什么**（缺口清单，这是"离题检测"）
- `reminder` — **硬约束**（每次都要提醒的红线）
- 可选：`can_write_code` 之类的**状态约束**

## 四、引导必须钉在状态文件顶部

脚本只是"能查到"，还得让 AI"想起来查"。

**做法**：把触发指令写进状态文件的第一屏。

```markdown
# {任务名}

> 🔁 **引导机制 —— 每个动作前先跑，不要凭记忆推进**
>
> ```bash
> python3 {脚本路径} {本文件路径}
> ```
>
> 它会返回：当前阶段 / 下一步 / 怎么做 / 缺什么。
```

**原理**：AI 会反复读状态文件（那是它的工作区）。"记得调脚本"是一条会沉底的提示词，但"文件第一行写着先跑引导脚本"挂在它必然经过的路上。

## 五、阶段状态机（脚本内置）

脚本内部维护阶段定义，每阶段带 `next` / `how` / `checklist`：

```python
STAGES = [
    {"id": "collect", "title": "Stage 0 接收澄清",
     "next": "问清三件事", "how": "只收事实",
     "checklist": ["触发场景", "产物", "判定标准"]},
    ...
]
```

**当前阶段 = 第一个未完成的阶段**（从状态文件解析 `- 状态：✅/🟡/⏸`）。

这样脚本既是引导器，也是状态机——不需要额外的状态存储。

## 六、反例（不要这么写）

| 反例 | 问题 |
|------|------|
| 脚本里写死"第 3 步做什么" | 状态变了它不知道，引导会错 |
| 依赖第三方库 | 换环境跑不起来，引导失效 |
| 脚本自动改状态文件 | 与 AI 的更新冲突，状态会乱 |
| 解析失败就报错退出 | 引导器应该"宽容"——解析不到就提示补齐 |
| 返回一大段文字没有结构 | AI 提取不到重点，等于没引导 |

## 七、测试要点

```bash
# 1. 新建任务（生成状态文件）
python3 xxx_guide.py --new "任务名"

# 2. 空状态下的引导（应提示补齐 + 列出缺口）
python3 xxx_guide.py <state.md>

# 3. 填充后的引导（缺口应消失，退出码 0）
python3 xxx_guide.py <state.md>

# 4. 阶段推进
python3 xxx_guide.py <state.md> --advance

# 5. JSON 模式（供程序处理）
python3 xxx_guide.py <state.md> --json
```

**退出码约定**：`0` 正常 / `1` 有阻塞缺口 / `2` 用法错误。
